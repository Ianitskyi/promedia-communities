# promedia-communities

Каталог і карта медійних спільнот України — база посилань на медіа: сайт,
короткий опис, ключова ідея спільноти та посилання, де на неї підписатися.
Кожен запис прив'язаний до області, тож на схематичній контурній карті можна
натиснути область і побачити медіа звідти.

🔗 Локально: відкрийте `index.html` подвійним кліком, або

```
python -m http.server 8080
```

і зайдіть на http://localhost:8080

## Двомовність: UA — обов'язково, EN — бажано

Сайт двомовний (UA/EN, перемикач `js/i18n.js`). Весь UI-текст (кнопки,
заголовки, підказки) вже перекладено — при будь-якій новій зміні тексту
інтерфейсу перекладайте одразу обидві мови в `js/i18n.js` (і в
`js/community-analysis.js` для розділу «Практикум»).

Дані каталогу (`data/communities.json`) — інша історія: `name`/`description`/
`communityIdea` вводяться українською (заявниками через форму `/add`, або
вручну), і переклад на англійську — окреме поле (`nameEn`/`descriptionEn`/
`communityIdeaEn`), яке потрібно додавати самостійно. Якщо перекладу немає,
сайт просто показує український текст і на EN-версії (тихий fallback, без
помилок) — але для якісної двомовності бажано заповнювати ці поля для
кожного нового чи зміненого запису.

## Формат запису (`data/communities.json`)

```js
{
  "id": "unique-slug",
  "name": "Назва медіа",
  "nameEn": "English name",        // опційно — якщо не задано, на EN-версії сайту показується "name" без перекладу
  "region": "Львівська область",   // текст, що показується на картці
  "regionEn": "Lviv Oblast",       // опційно — якщо не задано, на EN-версії сайту показується "region" без перекладу
  "regionSlug": "lviv",            // id області на SVG-карті — англ./укр. назви обох мов у js/i18n.js (oblasts.*)
  "regionSlugs": ["lviv", "kyiv-city"], // опційно — якщо медіа присутнє в кількох областях: картка враховується в лічильнику й фільтрі кожної з них на мапі, але лишається одним записом (не впливає на загальну кількість медіа). За відсутності поля використовується лише regionSlug
  "city": "Львів",
  "cityEn": "Lviv",                // опційно, той самий принцип, що й regionEn
  "website": "https://example.com",
  "description": "Короткий опис медіа (1-2 речення).",
  "descriptionEn": "English translation.", // опційно — якщо не задано, на EN-версії сайту показується "description" без перекладу
  "communityIdea": "Ключова ідея спільноти — чому варто підписатися.",
  "communityIdeaEn": "English translation.", // опційно, той самий принцип, що й descriptionEn
  "communityUrl": "https://t.me/example",
  "platform": "telegram", // telegram | facebook | instagram | youtube | viber | website | other — не збирається формою /add, за замовчуванням "other"; редагується вручну в /admin
  "badges": {
    "recommended": false, // на мапі рекомендованих медіа
    "whitelist": false,   // у білому списку ЗМІ
    "jti": false          // сертифікація Journalism Trust Initiative
  },
  "tags": ["investigative", "warJournalism", "culture", "science"], // опційно, будь-яка підмножина — див. I18N.*.tags у js/i18n.js
  "status": "approved",   // "approved" = видно на сайті; "pending" = нова заявка, ще не перевірена; будь-що інше = знято з публікації
  "example": false,       // true лише для ілюстративних seed-записів
  "logo": "https://www.google.com/s2/favicons?domain=example.com&sz=128", // опційно — іконка на картці; або фавікон сайту автоматично, або img/logos/<id>.<ext>, якщо заявник завантажив свій файл у формі /add
  "sourceIssue": 42,               // опційно — номер GitHub issue, з якого автоматично створено запис
  "sourceIssueUrl": "https://github.com/…" // опційно — посилання на той issue (показується в /admin)
}
```

`regionSlug` — один із 26 id, що відповідають областям на карті (`cherkasy`,
`chernihiv`, `chernivtsi`, `crimea`, `dnipropetrovsk`, `donetsk`,
`ivano-frankivsk`, `kharkiv`, `kherson`, `khmelnytskyi`, `kirovohrad`,
`kyiv`, `kyiv-city`, `luhansk`, `lviv`, `mykolaiv`, `odessa`, `poltava`,
`rivne`, `sumy`, `ternopil`, `vinnytsia`, `volyn`, `zakarpattia`,
`zaporizhia`, `zhytomyr`). Зверніть увагу: медіа зі штаб-квартирою в Києві
мають `regionSlug: "kyiv-city"` (місто), а не `"kyiv"` (область навколо
міста) — це дві різні фігури на карті.

⚠️ **Позначки `recommended` / `whitelist` / `jti` потрібно проставляти
свідомо**, звіряючись з актуальним реєстром білого списку ЗМІ та реєстром
сертифікації JTI — це не автоматично визначені поля.

Позначки й теги показуються лише на картці медіа (як опційні характеристики)
— на головній сторінці немає окремих кнопок-фільтрів за ними, лише пошук і
фільтр за областю.

**Публікація/зняття з публікації** відбувається виключно зміною поля
`status` цього ж запису — жодних окремих «активна/неактивна» таблиць немає.
Це можна зробити вручну на GitHub (Edit → змінити рядок → Commit) або
попросити мене (Claude) це зробити, якщо в мене є доступ до репозиторію.

## Редагування з адмінки ProMedia

Сайт підготовлено до сценарію, коли основна адмінка `promedia.report/admins`
редагує безпечні структуровані файли в GitHub через API. Для цього є файл
`content/site.json`:

```json
{
  "schemaVersion": 1,
  "admin": {
    "label": "communities.promedia.report",
    "repository": "Ianitskyi/promedia-communities",
    "editableFile": "content/site.json"
  },
  "i18n": {
    "uk": { "hero": { "title": "..." } },
    "en": { "hero": { "title": "..." } }
  }
}
```

`js/i18n.js` спочатку завантажує цей файл і накладає значення з `i18n` поверх
вбудованого словника. Якщо файл недоступний або містить помилку, сайт
працює на вбудованих текстах, тобто публічна сторінка не ламається.

Для CMS-плагіна це означає простий і безпечний контракт: читати
`content/site.json`, показувати поля як форму, після збереження робити commit
у GitHub. Код, стилі й `data/communities.json` можна залишити окремими
режимами редагування з вищим рівнем обережності.

## Наповнення даних: поточний стан

Каталог наповнено **46 реальними медіа** з робочою базою ProMedia (назва,
сайт і посилання на спільноту — з надійного джерела; область визначена за
вказаним у джерелі містом/областю).

**Опис (`description`)** знайдено окремо для кожного медіа — переважно зі
сторінок «Про нас» на їхніх власних сайтах (кілька — з надійних вторинних
джерел на кшталт Вікіпедії чи detector.media, коли прямої сторінки не було).
Два записи варто звірити з оригіналом вручну — позначені в
[`data/RESEARCH_NEEDED.md`](data/RESEARCH_NEEDED.md).

**Позначки `recommended`/`whitelist`/`jti`** теж проставлені за результатами
дослідження (мапа рекомендованих медіа detector.media+ІМІ, білий список ІМІ,
сертифікація JTI) — 26/3/6 медіа відповідно. Дві позначки `recommended`
варто звірити вручну (менш надійне джерело).

⚠️ **Ключова ідея (`communityIdea`) і теги (`tags`) досі навмисно порожні**
— окреме дослідження на майбутнє. На картці порожні абзаци просто не
показуються. Повний перелік того, що ще бракує по кожному медіа —
у [`data/RESEARCH_NEEDED.md`](data/RESEARCH_NEEDED.md); заповнення
найзручніше робити через `/admin` → «Редагувати на GitHub».

`logo` — іконка сайту, автоматично підтягнута через публічний сервіс
фавіконів Google (`google.com/s2/favicons?domain=…`) за доменом з `website`.
Це не офіційний логотип бренду, а фавікон сторінки — для більшості сайтів
виглядає пристойно, але варто перевірити візуально й за потреби замінити
`logo` на пряме посилання на офіційний логотип.

## Премодерація нових спільнот

«Базою даних» лишається сам файл `data/communities.json` у цьому
репозиторії — жодної окремої СУБД. Але щоб заявник **не бачив GitHub і не
мав GitHub-акаунту**, сайт має тонкий проміжний шар — один Cloudflare
Worker, який тримає єдиний секретний ключ і сам пише в GitHub від імені
відвідувача.

**Шлях заявки:**

1. Відвідувач тисне «Додати спільноту» → потрапляє на стилізовану сторінку
   [`/add`](add/index.html) (той самий дизайн, що на решті сайту),
   заповнює форму (назва, сайт, посилання на спільноту, опис, ідея,
   місто/область, позначки й теги — усе прямо тут, без переходів) і тисне
   «Надіслати заявку».
2. Форма відправляє `POST` на `communities.promedia.report/api/submit-community`
   — це Cloudflare Worker
   ([`cloudflare-worker/submit-community.js`](cloudflare-worker/submit-community.js),
   інструкція з деплою — [`cloudflare-worker/README.md`](cloudflare-worker/README.md)).
   Worker перевіряє обов'язкові поля й сам, через GitHub Contents API,
   дописує новий об'єкт у `data/communities.json` зі `"status": "pending"`
   — прямим комітом у `main`. Заявник бачить лише «Дякуємо, заявку
   надіслано» — жодного GitHub у нього на екрані.
3. Оскільки сайт показує лише `status === "approved"`, нова заявка ще **не
   видно на сайті**.
4. Модератор (ви) заходить на [`/admin`](admin/index.html) — там список усіх
   заявок «на розгляді» та вже опублікованих, з посиланням «Редагувати на
   GitHub» біля кожної.
5. **Щоб опублікувати** — тиснете «Редагувати на GitHub», у файлі
   знаходите потрібний запис (за `id` чи назвою), міняєте
   `"status": "pending"` на `"status": "approved"`, комітите. Запис
   одразу з'явиться на сайті після наступного деплою (автоматично, за
   push у `main`).
6. **Щоб зняти** вже опубліковану спільноту — так само редагуєте
   `status` на щось інше (`"pending"`, `"disabled"` тощо).
7. Якщо не хочете редагувати JSON вручну — просто напишіть мені (Claude) в
   чаті «схвали заявку №X» чи «зніми з публікації <назва>», і я зроблю
   заміну через свій доступ до репозиторію.

⚠️ **Форма не запрацює, доки Worker не задеплоєно** — це єдина ручна дія,
яку не можу зробити я сам (потрібен доступ до вашого акаунту Cloudflare).
Кроки — у [`cloudflare-worker/README.md`](cloudflare-worker/README.md),
займає 5-10 хвилин.

## Деплой і DNS

GitHub Actions (`deploy-pages.yml`) автоматично публікує сайт на GitHub
Pages при кожному push у `main`. Щоб субдомен `communities.promedia.report`
запрацював, потрібно:

1. У налаштуваннях репозиторію → **Settings → Pages** переконатися, що
   Custom domain = `communities.promedia.report` (файл `CNAME` це вже задає,
   GitHub Pages підхопить автоматично після першого деплою).
2. У DNS-панелі домену `promedia.report` додати `CNAME`-запис:
   ```
   communities.promedia.report  →  ianitskyi.github.io
   ```
   (аналогічно до вже налаштованого запису для `ratings.promedia.report`).
3. Увімкнути **Enforce HTTPS** у Settings → Pages після того, як DNS
   пропагується і GitHub видасть сертифікат.

## Карта

Замість реалістичної супутникової/вуличної карти сайт використовує
**схематичну контурну SVG-карту областей** — так простіше сприймати
географію на рівні областей, без зайвих деталей вулиць чи рельєфу.

Контури взято з пакета [`@svg-maps/ukraine`](https://www.npmjs.com/package/@svg-maps/ukraine)
(`img/ukraine-oblasts.svg`), який адаптує мапу [MapSVG](https://mapsvg.com/maps/ukraine)
за ліцензією [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) —
атрибуція вказана у футері сайту. `js/app.js` після завантаження SVG додає
обробники кліків на кожну область (`<path id="...">`), лічильник медіа
(`<text>` по центру фігури) та підсвітку — без сторонніх бібліотек для
карт.

## Мова (UA/EN)

Сайт має перемикач UA/EN у правому верхньому куті (`js/i18n.js`, той самий
підхід, що й у `journalism2026`): статичний текст перекладається через
`data-i18n(-html|-content|-placeholder|-alt|-aria-label)` атрибути в HTML,
динамічний (картки, лічильники на карті, підписи областей) — через
`t()`/`tRaw()` виклики в `js/app.js`, які повторно викликаються при зміні
мови (`window.onLangChange`).

Мову також можна задати напряму в URL — `?lang=en` або `?lang=uk` — це
дозволяє переходити з promedia.report чи `ratings.promedia.report` одразу в
потрібній мові. Посилання «← ПроМедіа» автоматично дописує поточну мову як
`?lang=`, щоб перехід назад теж був у ній.

**Обмеження:** перекладається лише інтерфейс сайту (заголовки, кнопки,
назви областей, позначки/теги, форма `/add`). Самі дані медіа (назва, опис,
ключова ідея спільноти) — одномовні, українською, як їх вносить модератор.
Сторінка `/add` двомовна, але фінальний крок (сам GitHub Issue) — завжди
українською, бо шаблон `add-community.yml` одномовний.

## Ліцензія на дані

Дані каталогу — оригінальний контент, зібраний і промодерований командою
ПроМедіа та спільнотою. Перед публічним запуском варто визначити умови
використання (ліцензію) для `data/communities.json`.
